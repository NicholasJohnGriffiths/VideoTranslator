# VideoTranslator

ASP.NET Core Razor Pages upload, storage, audio extraction, English transcription, script review,
timed speech generation, subtitles and final video rendering
for a general-purpose video translation app.
Targets .NET 10, the supported SDK installed in this development environment. No database.

## Live Azure app

The app is deployed at `https://videotranslator-tinumbraco.azurewebsites.net/` on the existing
New Zealand North `tinumbraco-plan`. Sign in with the configured shared account described below.
Azure upload, English Speech transcription, private-endpoint GPT-4o translation, script review,
voice previews, timed audio and final MP4 rendering are enabled. No separate processing app or
new paid hosting plan is used. Local OpenAI remains disabled because this development machine
does not have private routing; do not run its worker against the same container as Azure.

On 5 October 2026 a synthetic 12-second English video completed every stage in the hosted app,
using managed identity for Blob, Speech and OpenAI. Private-only OpenAI returned a real translation;
the final 640x360 MP4 contains H.264 picture, replacement AAC audio and mov_text subtitles.
Browser playback, UTF-8 WebVTT, approved script/video downloads, HTTP ranges and completion
SHA-256 checksums were verified. The timed PCM was exactly 12 seconds with preserved leading/trailing
silence, and the rendered H.264 picture packets matched the original byte-for-byte. After restarting
only the new app, the signed-in session and checksum-identical completed output remained available
without another AI request. The exact synthetic job and local test files were then removed.
Full regression validation passed 271 tests.
This short test is not certification of long-video capacity: the shared B1 plan has limited headroom.
Process one job at a time, review output before rendering, and monitor CPU/memory/disk.

## Run locally

```powershell
dotnet restore VideoTranslation.slnx
dotnet build VideoTranslation.slnx
dotnet run --project VideoTranslator --launch-profile http
```

FFmpeg and FFprobe are required at startup. On this Windows development machine they were installed
with WinGet (`Gyan.FFmpeg`). Development configuration uses the WinGet executable aliases under
`%LOCALAPPDATA%\Microsoft\WinGet\Links`. If installed elsewhere, set `Media__FFmpegPath` and
`Media__FFprobePath` to the executable paths. On Linux use `ffmpeg` and `ffprobe` on PATH
(the base configuration defaults) or configure absolute paths. Do not use Windows Development
path overrides on Linux.

Run `az login` first, using the Azure subscription containing `tinumbracost`.
Local Development now defaults `AzureHosting:ProcessingEnabled=false`: starting the debugger
does not run a second queue worker against the live Azure container. To process local jobs, explicitly
set `AzureHosting__ProcessingEnabled=true` and use local storage or a separate development container.
Never enable a local worker on the live container while the Azure worker is enabled.
Development configuration now selects Azure Blob storage and authenticates explicitly with
your Azure CLI identity. The identity needs **Storage Blob Data Contributor** scoped to
the `video-translation-jobs` container. Subscription Owner is not sufficient for Blob data uploads.
The current developer's user has been granted this container-scoped role with approval.
Other users need their own approved assignment.

Open http://localhost:5045. Select an English MP4 (up to 100 MB), choose Mandarin Chinese,
Arabic, Spanish or Hindi, and upload. The job page displays a persistent random job ID,
selected language, upload size and status. It refreshes while queued/extracting. Valid MP4s with
both video and audio tracks progress through **AudioReady** and **Transcribing** to **TranscriptReady**;
invalid media or transcription failures progress to **Failed** with a useful message.
Use **View English transcript** to review each recognised phrase with its start/end timestamps.
Uploads incur Azure Storage usage charges,
and transcription incurs Speech charges. Local OpenAI translation remains disabled because private
routing is unavailable on this machine. Hosted Azure translation is enabled and verified.
Saved translations can be reviewed and edited; no sample translation is generated by the app.

To use local files and disable all Azure processing:

```powershell
$env:JobStorage__Provider = "Local"
$env:AzureHosting__ProcessingEnabled = "true"
$env:AzureSpeech__Enabled = "false"
$env:AzureSpeech__SynthesisEnabled = "false"
$env:AzureOpenAI__Enabled = "false"
dotnet run --project VideoTranslator --launch-profile http
```

Remove those environment variables to return to the Azure-enabled development defaults.
Choosing local storage alone does not disable Speech transcription, synthesis or OpenAI.

```powershell
dotnet test VideoTranslator.Tests\VideoTranslator.Tests.csproj
```

## Implemented scope

- Razor Pages home, upload, job, time-coded transcript, storage/privacy and error pages.
- Core job, segment, transcript, translation and language models.
- Configuration-driven languages/voices, including Arabic RTL metadata.
- Strongly typed options; active local options validated at startup.
- Service contracts for storage, transcription, translation, synthesis, timing, subtitles and rendering.
- Dependency injection for working local upload, validation, language and storage services.
- Local persistent job JSON and server-named MP4 files outside the public web root.
- Azure Blob job storage with Azure CLI development credentials and managed identity configuration
  for Azure hosting; provider selection rejects unknown providers without falling back to local files.
- Startup check for an existing private container; startup fails on missing container, inaccessible
  container settings or anonymous access. This checks configuration/read access, not data-write RBAC.
- Blob uploads enforce size and signature validation before contacting Azure, and publish metadata last
  using create-only conditions. Partial failure cleanup cannot overwrite existing jobs.
- Extension, MIME, size and basic MP4 container-header validation.
- Staged uploads: incomplete/invalid uploads are removed before publishing a job directory.
- Unit tests with no live Azure dependency.
- FFprobe checks MP4 container, positive finite duration and video/audio tracks.
- FFmpeg decodes the first audio track to mono, 16 kHz, signed 16-bit PCM WAV.
- FFprobe verifies the generated WAV has that exact format and a positive duration before it is saved.
- Process invocation uses argument lists (not a shell), disables stdin and network protocols,
  limits decoding/encoding threads to one, drains bounded diagnostics, and kills the child process
  tree on cancellation/timeout. Default per-command timeout: 600 seconds.
- One background worker scans persistent jobs every 5 seconds, processes jobs sequentially,
  saves audio before marking AudioReady, and persists safe media-failure messages.
- Interrupted ExtractingAudio jobs resume from their original upload after restart.
- Blob status updates use ETag conditions; local metadata updates use atomic replacement.
- Keyless Azure Speech fast transcription using an English locale, authenticated multipart audio
  upload and phrase timestamps. No keys or signed audio URLs are used.
- English transcript JSON persisted before TranscriptReady status, with ordered numbered segments.
- Saved transcripts reused after interruption to avoid unnecessary repeat transcription.
- Safe failures for empty recognition, malformed responses, invalid timestamps, HTTP errors,
  authentication errors and timeout. Failure stage is saved with the job.
- Keyless Azure OpenAI structured translation implementation with bounded batches, exact segment IDs,
  original timestamps/source preserved, explicit errors and no HTTP retries. Disabled by default.
- Private-only OpenAI transport: approved DNS addresses, pinned private sockets, normal hostname TLS,
  no proxies, no redirects and no public fallback.
- Immutable original translation JSON and separately persisted edits; durable translation recovery.
- Script review/editor with timestamps, English source, original translation, per-segment reset,
  deliberate empty edits, Arabic RTL, HTML encoding, antiforgery and optimistic concurrency.
- Keyless on-demand Azure Speech synthesis and per-segment audio previews using the configured voices.
- Current (including unsaved) edit previews, immutable private PCM WAV cache, range-enabled audio playback,
  measured duration versus the source slot, and rejection of blank, invalid or truncated synthesis output.
- Explicit saved-script approval, frozen generation snapshots, restartable full audio generation,
  pitch-preserving timing up to 2.00x for new approvals, exact silence/padding, and private full WAV playback/download.
- Confirmed final rendering: UTF-8 WebVTT, effective approved script download, MP4/H.264/AAC with
  replaced audio and switchable subtitles, private playback/ranges and durable recovery.

- Protected single-account Azure login, secure sessions, logout, login throttling and fail-closed hosting validation.
- One deployed Azure app with VNet integration, scoped managed identity and verified private OpenAI requests.

**Not implemented:** automatic retention, individual user isolation/MFA, overlapping-speaker dubbing
or post-completion regeneration.
With the default local disabled OpenAI configuration, valid jobs stop at TranscriptReady
(or AudioReady when Speech is disabled). With verified private OpenAI enabled, they stop at
AwaitingScriptReview. Saving edits never triggers later processing. Explicit approval can queue full audio generation.
There is no simulated translation.

The supplied instructions' section 29 defines an incremental first phase, whereas section 33
calls the complete workflow "Phase 1". The initial scaffold followed the explicit first task in section 34 and stopped for review.
The subsequent approved phases add Blob storage, media validation, background audio extraction,
English Speech transcription, private-only translation implementation, script editing, voice previews
and full audio generation, subtitles and rendering.

## Configuration and storage

Non-secret configuration lives in `VideoTranslator/appsettings.json`.
Base configuration selects local storage. Development configuration selects Azure Blob storage.
Local storage is `VideoTranslator/Data/jobs/{jobId}/`, containing `job.json` and
`original-video.mp4`, `original-audio.wav` and `transcript.json` after processing.
Translation adds `translation.json`; edits add `edited-script.json` (with a unique revision).
Data and build output are ignored by Git. Files survive local application
restarts; they are not automatically deleted. Failed staging uploads are cleaned up when possible,
with cleanup failures logged. An abrupt process termination may leave a `.upload-*` directory;
inspect and remove those specific directories while the app is stopped.

The 100 MB limit is enforced during copying as well as metadata validation. Request limits allow
1 MB of multipart overhead. Larger requests can be rejected by the web server before page validation.
The upload header check is not full media validation; FFprobe and FFmpeg validate/decode media
asynchronously after upload. A job ID confirms storage, not successful media processing.
The app cannot determine whether uploaded speech is actually English yet.

Blob layout:

```text
video-translation-jobs/
  jobs/{jobId}/
    job.json
    transcript.json
    translation.json
    edited-script.json
    previews/{sequence}-{text-and-voice-hash}.wav
    generated/{requestId}/translated-audio.wav
    generated/{requestId}/timing.json
    rendered/{requestId}/subtitles.vtt
    rendered/{requestId}/approved-script.json
    rendered/{requestId}/translated-video.mp4
    rendered/{requestId}/result.json
    original/original-video.mp4
    working/original-audio.wav
```

The container is private (anonymous access off), on `tinumbracost` in New Zealand North.
The storage account's existing containers and public-network configuration were not changed.
A private container is not a network private endpoint; this phase uses authenticated HTTPS.

Blob uploads use a uniquely named temporary file on this machine and remove it in `finally`.
Original video is uploaded first; metadata publication marks a job as available. Failed publication
attempts clean up the original with an independent bounded timeout. If metadata exists after an
ambiguous failure, preserve the original to avoid damaging a committed job. Cleanup failures are logged.
Abrupt termination or lost responses can leave orphaned data; no automatic retention policy is wired yet.
Use only explicitly identified job paths when manually cleaning up.

Azure errors are logged server-side and displayed as safe storage-unavailable messages, not missing
jobs or successful uploads. Only an exact BlobNotFound response means a job was not found.
No storage keys, SAS credentials or connection strings are used by the application.

## Background processing

Run **one application instance per job store** in this phase. This is a low-volume, single-instance
worker, not a distributed queue/lease system. Do not run multiple instances or scale out against
the same container. ETags prevent stale metadata writes but do not replace a distributed worker lease.
Before scaling out, replace scanning with a durable queue and per-job claims.

The persistent job metadata acts as the pending-work source, so uploads are not lost if the process
stops after saving a job but before processing. Existing Uploaded and ExtractingAudio jobs are picked
up automatically. With Speech enabled, AudioReady and interrupted Transcribing jobs are also
picked up. With OpenAI enabled, TranscriptReady and interrupted Translating jobs are picked up.
With OpenAI disabled these jobs are left unchanged; Failed jobs are not reprocessed.
Storage outages are explicitly logged; pending jobs remain recoverable and are retried on later scans.
No in-memory success status substitutes for a failed persistent update.

Each attempt uses a unique temporary directory and cleans it on completion, failure or graceful
cancellation. Extracted WAV is persisted before status is marked AudioReady. It can be larger than
the compressed input, and Azure-mode processing downloads the original video, so allow temporary
disk space and transfer charges. Audio is overwritten on recovery attempts; originals are not modified.
Scanning lists the dedicated container and reads job metadata every 5 seconds, including finished jobs;
these transactions are billable. Increase `Media:PollIntervalSeconds` to reduce idle transaction usage.
A later queue/retention phase should eliminate repeated scans of retained finished jobs.

The process timeout bounds processing time, not total stored media duration. There is no language
detection or voice generation yet. Invalid/corrupt media, missing audio, decoder
errors and tool timeout are reported as Failed, with technical diagnostics in server logs.

## English Speech transcription

With approval, `speech-tinumbraco-video` (SpeechServices S0, pay-as-you-go) was created in
**Australia East**, under `rg-tinumbraco-prod`. The developer's signed-in user was granted
**Cognitive Services Speech User** scoped only to this resource.

Development configuration enables transcription and synthesis and uses Azure CLI identity. Base configuration
disables both and selects ManagedIdentity for future deployment. Azure CLI mode is rejected
outside Development. Future hosted identity needs the Speech User role on this resource separately
from its Blob role. Configure an optional user-assigned client ID if needed.

Endpoint: `https://speech-tinumbraco-video.cognitiveservices.azure.com/`.
Uses the fast transcription REST endpoint `speechtotext/transcriptions:transcribe`, API version
`2025-10-15`, and `https://cognitiveservices.azure.com/.default` token scope.
`AzureSpeech:SourceLocale` defaults to `en-NZ` and is configurable to another supported English
locale. Recognition is not English-language detection or a translation service.

Extracted audio is sent from this machine/storage in New Zealand to Speech in Australia East.
Speech uses authenticated HTTPS on a publicly reachable custom endpoint, **not a private endpoint**.
OpenAI uses a separate private-only transport; it is enabled in Azure after verified routing and permissions,
but remains disabled locally.
Speech and storage/transfer usage are billable. Speech S0 does not imply free-tier allowances.
Fast transcription pricing is different from batch transcription; check the current regional
fast-transcription meter for budgeting.

Fast transcription accepts audio below 500 MB and 5 hours; oversized extracted PCM audio is
rejected with a clear message. Default request timeout is 600 seconds. HTTP requests are not
automatically retried, to avoid hidden duplicate billable calls. Speech failures mark the job Failed;
upload again after correcting the problem. Shutdown leaves Transcribing jobs eligible for recovery.
If a response or transcript write is lost before durable storage, recovery can incur another Speech
call. If transcript JSON was committed, the worker reuses it before making another request.

The parser consumes `phrases`, not the combined text, requires non-empty speech and valid
millisecond offsets/durations, orders segments by start/end, and preserves the timestamps.
Segments are stored as `Sequence`, `Start`, `End`, `OriginalText` with translation/edit fields empty.
Silent/no-speech audio is an explicit failure. Overlapping phrase timings are preserved rather than
inventing new timestamps. Human review remains necessary; recognised text is HTML-encoded in the UI.

Default local Development has no user authentication; random job URLs are not access control.
Do not expose development publicly or upload sensitive content to a shared instance.
Production startup requires the explicit protected Azure configuration described below.
HTTP is used for loopback development only; production must enforce HTTPS.

## Private OpenAI translation and script editing

Both source-controlled base and Development settings keep `AzureOpenAI:Enabled=false`.
The hosted Azure app overrides this to true after private DNS, socket routing and managed-identity
RBAC were verified through its private-only client with a real synthetic translation.
The development machine currently resolves the OpenAI hostname to a **public** address, so it cannot
use OpenAI privately. No live OpenAI call or new OpenAI role grant was made during this phase.
Read-only follow-up confirmed the developer already has OpenAI User permission, but TCP access
to `10.20.2.4:443` fails and no Azure VPN gateway exists in this subscription.
The existing private endpoint NIC reports `10.20.2.4`; this is the exact configured allowlist.
Never enable translation as a way to bypass networking. Do not disable existing consumers' public
access settings or change shared networking without approval.

Before enabling, establish approved VNet/VPN connectivity, verify private DNS, actual private routing
and a resource-scoped **Cognitive Services OpenAI User** role for the execution identity.
An enabled app checks DNS at startup and refuses public/unapproved DNS results. Every new HTTP
connection rechecks DNS and pins its socket to an approved RFC1918 IPv4 address, with normal TLS
hostname validation. Proxies and redirects are disabled. DNS success alone does not prove routing.
No public endpoint fallback, keys or automatic HTTP retry are used.

Configure `AzureOpenAI:Endpoint`, `DeploymentName`, `PrivateEndpointAddresses`, `CredentialMode`
and optional `ManagedIdentityClientId`. Development selects AzureCli; base selects ManagedIdentity.
CLI credentials are prohibited outside Development. API version is `2024-10-21` with GPT-4o
`2024-11-20` structured output. Default request timeout is 120 seconds, with up to 20 segments
and 16,000 source characters per batch. Oversized individual segments fail explicitly.
Responses require exactly the source IDs and complete, non-empty translations; refused, truncated,
duplicate/missing IDs, oversized or malformed responses fail without inventing data.
The application copies timestamps and source text from its transcript, never model-generated values.

Text goes to Australia East, even though the private endpoint and storage are in New Zealand.
OpenAI token charges and storage/transfer charges apply when enabled. Translation files are saved
before AwaitingScriptReview. Interrupted jobs reuse saved translation rather than calling OpenAI
again. If a response/write is lost before persistence, or a later batch fails, another attempt can incur
repeat charges. Failed jobs require a new upload after correcting the cause.

At `/jobs/{jobId}/script`, the editor shows English, machine translation, timings and editable text.
Typing automatically unchecks **Use original translation**; without JavaScript, uncheck it to use an edit.
Check it to reset. An empty edit is intentional,
and is not replaced with machine translation. Edited text is limited to 8,000 characters per segment.
Original translations are create-only and never overwritten by edits. Local edits use atomic
replacement with unique revisions; Blob edits use ETag If-Match/create-only conditions.
A stale save returns HTTP 409 without overwriting and leaves submitted text visible for copying;
reload before reapplying edits. One application instance is still required.
Saving leaves the job AwaitingScriptReview; explicit approval is required for full translated audio.

## Voice preview and synthesis

With approval, per-segment previews reuse the existing `speech-tinumbraco-video` resource.
No new resources, keys or networking changes were needed for the original local preview phase.
That phase used explicitly synthetic translated scripts, not simulated OpenAI output in the app.
The subsequent Azure deployment uses its own scoped identity and verified real OpenAI translations.

`AzureSpeech:SynthesisEnabled` is **true** in Development and false in base configuration.
It is independent of `AzureSpeech:Enabled` (transcription); disable **both** for no Speech calls.
The synthesis client uses the custom endpoint `/tts/cognitiveservices/v1`, the existing explicit
credential mode, and a keyless `Bearer aad#{resourceId}#{entraToken}` authorization value.
`AzureSpeech:ResourceId` must be the full Speech resource ID, not a secret.
`AzureSpeech:SynthesisTimeoutSeconds` defaults to 120. Redirects and automatic HTTP retries are disabled.
Use the existing resource-scoped Speech User role; subscription Owner alone is not sufficient.

Each editor segment has **Preview voice**. It synthesizes that segment's current text (including
unsaved edits), or the machine translation if **Use original translation** is checked.
It does **not** save edits, change status, regenerate the video or preview other segments.
The submitted form and edit revision are preserved so a subsequent save still detects stale tabs.
Blank/whitespace edits cannot be voiced; they produce an explicit message without calling Speech.
Text is limited to the editor's 8,000-character limit and encoded as XML text, never interpreted
as user-supplied SSML. Configured locale/voice select the language. User text cannot insert audio
URLs, SSML commands or custom voices.

Speech generates mono 16 kHz 16-bit PCM WAV. Responses are size-bounded and RIFF/chunk/format/sample
validated before storage. Empty, malformed, incorrect-format and 10-minute service-limit audio are
rejected rather than presented as successful previews. No timing adjustment is applied yet.
The editor displays measured audio duration versus the source slot and warns when speech is longer.
Typing or changing the original/edit selection removes the displayed old preview to avoid stale playback.

Previews are private files in each job's `previews/` directory (same layout for local and Blob modes).
The cache key includes exact text, voice, locale, audio format and a version. Identical requests reuse
durably saved audio without another synthesis call, including after app restart.
Changed text/voice generates a separate cache entry; old versions remain until manual job cleanup.
Even unsaved text is represented in retained preview audio. Temporary generation files are removed
on success/failure/cancellation; abrupt crashes can leave temporary folders.
Failed storage after synthesis or a lost response can lead to another billable synthesis request.
One preview request is processed at a time per app instance; concurrent requests return an explicit
busy response (HTTP 429). This is not distributed locking or a production rate limiter.

Audio is served through the application at `/jobs/{jobId}/preview/{sequence}/{key}`, with `audio/wav`,
no-store, nosniff and HTTP range support; no SAS or public Blob URL is issued. GET never synthesizes.
Existing cached audio remains readable when synthesis is disabled. Invalid/missing preview identifiers
return 404; storage failures return 503. Default local Development has no user authentication: random URLs and
private Blob storage are **not** authorization. Keep development private; the Azure deployment requires
the configured authentication mode before serving these routes.

Preview text crosses New Zealand's border to Speech in Australia East over authenticated public HTTPS,
not an OpenAI private endpoint. Synthesis is character-billed and distinct from transcription pricing;
storage/read/transfer charges also apply. Live validation generated short Arabic, Spanish, Mandarin
and Hindi samples, decoded them in the browser and checked persistent caching.

## Full translated audio and timing

### Estimated per-job AI costs

Job details, completed results and My videos display a persistent **estimated NZD AI cost**.
It is not an Azure invoice and excludes shared hosting, storage, transfer, private networking,
tax, negotiated discounts and free allowances. Existing jobs are explicitly labelled as incomplete
history; no historical usage or zero-cost claim is invented.

Each live request records a create-only usage-start event before sending, then a completion event
when usage is confirmed. Interrupted/failed requests or OpenAI responses without token usage remain
unresolved and are excluded from the known subtotal with a warning. Storage failures are explicit;
the app does not send a tracked request if its start event cannot be saved. Retried service calls
are separate requests. Cached transcripts, translations and exact-text voice previews incur no new
tracked AI charge. All synthesized previews, including unsaved text, count when sent to Speech.
Counts contain no transcript text, credentials or user media.

Rates are configurable under `JobCosts`, snapshotted into each completion record, not applied
retroactively. Defaults verified against the public [Azure Retail Prices API](https://prices.azure.com/api/retail/prices)
on 2026-10-05 for Australia East:

| Meter | NZD retail rate |
|---|---:|
| Fast Transcription | 0.6360 / hour |
| S1 Neural Text To Speech | 26.4994 / million text characters |
| GPT-4o 2024-11-20 Standard regional input | 0.0049 / 1,000 tokens |
| Cached input | 0.0024 / 1,000 tokens |
| Output | 0.0194 / 1,000 tokens |

OpenAI token counts come from each response, including cached input. Transcription duration comes
from the PCM audio inspector. Synthesis uses Unicode text character counts (SSML markup excluded),
which may differ from Azure's billing rules. Rates are a fixed snapshot, not a live pricing feed;
update settings and `RateDate` if service SKU, region, model or retail pricing changes.

The job page shows a compact progress bar beside each stage. Completed stages are full;
processing stages animate without claiming a measured percentage. Queued, waiting, disabled,
review-required and failed stages have explicit labels. Existing five-second refreshes update
processing stages. Animation respects reduced-motion preferences; review and rendering still
require explicit approval.

Upload, job status, transcript, script review, audio review and result pages have a prominent
**Next step** panel. Status guidance distinguishes automatic processing, disabled processing,
script approval, rendering approval, failures and completion. Script instructions link to saving
and audio approval; audio instructions link to rendering confirmation. These links never approve
or queue work themselves, and existing confirmation/charge controls remain required.

The confirmed plan uses Azure OpenAI for translation, enabled on the privately connected Azure host.
The current timing policy for new approvals is **up to 2.00x pitch-preserving acceleration**;
never cut words off or shift source segment starts to force a fit.
New approvals allow speech to continue through the following silence until the next segment starts;
the last segment may continue until the video ends. Natural speed is used whenever it fits that
available window, with acceleration only when necessary. Even a deliberately blank next segment
retains its start boundary. Source timestamps and subtitle timings remain unchanged.
The user increased the initial 1.25x limit to 1.75x after a Mandarin segment required 1.63x,
then approved 2.00x after another segment required 1.96x.
Existing frozen approvals retain their stored limit, including legacy approvals whose missing
speed field defaults to 1.25x. Missing gap-policy fields retain the original end-boundary behavior.
Reapprove a job returned to review to use the new limit and available-gap policy.
Faster speech may sound rushed. If a segment still exceeds 2.00x, shorten and save its wording
before approving again; repeating approval of unchanged overlong text cannot resolve the timing issue.

At script review, save edits first, check the explicit approval/charges checkbox and choose
**Generate full translated audio**. Stale script revisions and unsaved effective-text changes are
rejected (409), missing approval is rejected (400), and an entirely blank script cannot be approved.
The app freezes the saved effective text, voice, locale, segment IDs/timestamps, revision and speed
policy into `job.json` with a unique generation request ID in the same status update that queues
GeneratingSpeech. Processing never reads a moving edited script. Later saves are rejected once the
job leaves review; a save already in flight cannot change the approved snapshot.

The single persistent worker resumes GeneratingSpeech jobs after restart when synthesis is enabled.
It obtains the original video's duration and rejects overlapping or out-of-video time slots **before**
synthesis. Overlapping speaker dubbing is not yet supported: it is reported explicitly rather than
merging segments, shifting timestamps or mixing voices incorrectly. A transcript timing correction
workflow is not yet available; such a source needs corrected segmentation before retrying.
Videos must be shorter than five hours; generated artifacts are bounded at 600 MB.

Each nonblank approved segment reuses the exact-text/voice preview cache or makes one keyless
Speech request. Blank/whitespace segments deliberately remain silent. Raw audio is persisted before
assembly, allowing restart/review retries to reuse synthesis. Preview and full-generation requests
share the same synthesis gate; if a preview is busy, the queued job waits for a later scan.

The separate timing service uses FFmpeg `atempo` to accelerate only longer speech without changing
pitch, measures the fitted output, and refuses to truncate any speech that still exceeds its slot.
It first tries the necessary ratio with a small safety margin, then the approved maximum if required.
Shorter speech is padded with silence to its approved window boundary (not slowed down).
FFmpeg creates silence for leading/gap/blank/
trailing intervals, assembles sequential PCM clips, and verifies the final duration against the video
to within one 16 kHz sample. Segment timing metadata records raw duration, slot length and applied speed.
Timestamps are rounded to the nearest sample rather than invented or shifted.

If speech requires more than its frozen approved limit (2.00x for new approvals) or cannot fit cleanly,
the job returns to AwaitingScriptReview
with the specific issue and no completed full track. Shorten and save wording, then approve again.
Very short slots may not accommodate even a short word within the speed limit; the app does not
silently relax the policy. A deliberate blank segment remains silent, but at least one segment must
contain speech for approval.
Cached raw previews remain for reuse. Speech/media failures are logged and persisted as Failed.

Full audio generation checks every nonblank segment against the frozen speed limit before assembly,
instead of stopping at the first overlong segment. All measured overlong segments are reported together
and flagged beside their text in script review. The report is saved with the job and describes the
last attempt, not subsequently edited text. Reapproval clears the old report and checks again.
This may synthesize additional segments on the first failed attempt; each is cached for later reuse.
Processing/storage errors and cancellation still stop processing explicitly rather than claiming
that unchecked segments passed. A timeline validation or fitted-audio assembly error can still return
a separate review message.
Storage outages leave generation pending and logged; no success status substitutes for failed storage.
Corrupt metadata/audio requires administrator repair rather than silent regeneration.

The complete WAV is persisted under the approved request ID before its create-only timing manifest;
only then does the job become **TranslatedAudioReady**. The worker can replace incomplete audio
before a manifest is committed, but never overwrites a committed result in this single-instance phase.
Restart recovery loads and verifies the committed PCM format/duration and completes the status without
calling Speech again. An interrupted assembly without a manifest is rebuilt from cached segments.

At `/jobs/{jobId}/audio`, listen, inspect per-segment speed/durations, or download the WAV.
This is **not a rendered translated video** and does not mark the job Completed. Confirm rendering
separately on this page. The full track preserves silence and video-length timing and uses mono 16 kHz
16-bit PCM. Audio routes provide no-store/nosniff and range requests through the app, never public Blob
URLs or SAS. Downloads are streamed through unique temporary files removed on close; a crash may
leave files requiring manual cleanup. Output and frozen-script versions remain until manual job deletion.
Original video, machine translation and source transcript are not modified.
Changing or regenerating an already completed full track is not yet exposed in the UI.

## Subtitles and final MP4

The user-selected output policy is **replace original audio, switchable subtitles, separate WebVTT**.
Existing audio-ready jobs do not automatically start rendering. On audio review, check the replacement
confirmation and choose **Render final video**. Missing consent returns 400; a duplicate or wrong-stage
request returns 409. This queues CreatingSubtitles, then RenderingVideo, then Completed only after all
files and a create-only completion manifest are durably saved. The final processor is independent of
Speech/OpenAI feature flags, and never invokes AI services.

Subtitles use the same frozen effective text and original transcript time slots, not live edits or
the original machine translation. Deliberately blank segments produce no cues. WebVTT is UTF-8 without
a BOM and uses millisecond timestamps, literal markup escaping, and nonblank lines within each cue
(blank lines cannot split a user's text into injected cues). Arabic, Hindi, Mandarin and Spanish are
preserved. Browser subtitle shaping/bidi display uses the player's Unicode support, not burned-in fonts.
The approved script download is JSON containing effective approved text, English source, timestamps,
language/voice, request ID and revision. Original transcript/translation files are not changed.

The isolated FFmpeg renderer maps only the first source video, the approved timed WAV and generated
subtitles. Original audio, previous subtitle/data tracks, chapters and user metadata are not copied.
H.264/yuv420p video is stream-copied; other video codecs/pixel formats are re-encoded with libx264,
yuv420p, CRF 20 and one thread. Odd-dimension sources needing re-encoding are rejected rather than
silently resizing the picture. Output uses AAC and MP4 `mov_text` switchable subtitles, fast-start MP4,
and no `-shortest` or subtitle-burning filter. Compatible source video packets are unchanged.
FFprobe verifies exactly one H.264 video, one AAC audio and one mov_text subtitle track, source picture
dimensions/display rotation, and total duration within 150 ms of the approved audio/video
(container/AAC timing tolerance). Automatic picture rotation is disabled during conversion so stored
dimensions and display rotation are preserved rather than unexpectedly swapping width and height.
Rendering is bounded by the existing process timeout, 600 MB output limit and five-hour media limit.
Long videos may need a configured timeout adjustment and sufficient disk; no silent fallback is used.

Rendering work is sequential in the existing single-instance persistent worker. Staged text/video files
may be replaced before `result.json` is committed. The manifest records sizes and SHA-256 checksums
for all three artifacts. Interrupted jobs with a committed manifest verify files, checksums, frozen text
and MP4 tracks/duration before completing, without rendering or synthesizing again. Without a manifest,
rendering restarts from approved artifacts. Storage/cancellation leave a recoverable pending stage;
media/source validation failures are logged and saved as Failed. Corrupt metadata/artifacts are logged
and remain pending for administrator repair, not silently regenerated or shown as success.
These operations assume one worker instance; ETags do not implement distributed render claims.

At `/jobs/{jobId}/result`, play the video or download video, subtitles and approved script. Browser
subtitles load the separate WebVTT because native MP4 subtitle-track support varies; downloaded MP4s
include the mov_text track for compatible players.

Browser subtitles are shown by default, with a **Show subtitles** checkbox synchronized with the
player's subtitle menu. Downloaded MP4 subtitle visibility depends on the player's track selection;
subtitles remain switchable, not burned into the picture.

Files are copied to unique delete-on-close temporary
streams and checksum-verified before serving. Video supports ranges; all output routes use no-store
and nosniff. Playback requires temporary disk and a private-storage read per request/range and may incur
storage/transfer charges. GET never queues work. A crash can leave temporary folders/files for cleanup.
Random URLs remain **not authentication**: keep the development app private.

Rendering adds CPU, disk, storage/transfer usage but no new Azure resources or Speech/OpenAI charges.
Rendering itself does not make translation requests; translation occurs before script review.
Local uploads stop at TranscriptReady while local OpenAI is disabled.

## Initial shared-account login

The requested Azure access mode is now `AzureHosting__AuthenticationMode=SingleAccount`, using the
configured username `Sanjeev`. `/Login` is a responsive username/password screen; all job pages,
uploads, script edits, previews and media/download endpoints require a valid app session. Public
CSS/JavaScript and the generic error page contain no job data. Microsoft sign-in is not required in
this mode. The earlier Entra registration can remain dormant; it is not used to authorize shared-account
sessions. `MicrosoftEntra` remains available as an explicitly configured alternative, not a fallback.

**Never put the password or its hash in source control.** Set `SingleAccountLogin__Username` and
`SingleAccountLogin__PasswordHash` in secure Azure app configuration. The hash format is
`pbkdf2-sha256:600000:<Base64 16-byte random salt>:<Base64 32-byte derived key>`.
Derive the key with PBKDF2-HMAC-SHA256 using 600,000 iterations. Missing, malformed or unsupported
credentials stop startup in shared-account mode; there is no default password or plaintext fallback.
The deployment template accepts the hash as a secure parameter, alongside `authenticationMode`
and `singleAccountUsername`. Default local Development remains unchanged; enabling shared-account
mode locally also requires credentials and HTTPS.

Sessions use an encrypted/signed, Secure, HttpOnly, SameSite=Strict `__Host-` cookie with an eight-hour
absolute lifetime and no persistent remember-me setting. Configure `SingleAccountLogin__KeyDirectory`
as `/home/videotranslator-auth/keys` on App Service so restarts retain the cookie-protection key ring;
startup rejects a key directory inside the public web root. Protect this directory and deployment
configuration from unauthorized administrators. Key-ring XML is not additionally encrypted by the
application, so access to these files must remain restricted. Changing the configured password hash
invalidates existing sessions on their next request.

Login and logout POSTs require antiforgery tokens; return URLs must be local. Incorrect credentials
produce a generic failure without logging passwords. The single app limits login POSTs to five per
minute globally, including successful attempts; excess attempts receive HTTP 429 and a retry hint.
This in-memory limit resets on restart and is intended for the existing single-instance deployment.

An invalid sign-in antiforgery token (for example, an old mobile browser tab whose cookies have
changed) rejects the submission and redirects to a fresh form with an explanation instead of a
blank HTTP 400. Credentials are not replayed; enter them again. If this repeats, check that browser
cookies are enabled. Other pages retain their normal antiforgery rejection behavior.

Logout is POST-only. Signing out removes this browser's cookie, rather than revoking another browser's
session; rotate the hash to invalidate every session.

This is a temporary shared-account access model, not individual users, MFA, password recovery or
per-user job isolation. Everyone with this login can access all jobs. Rotate the initial password before
broader use and move to individual identities when multiple users or sensitive footage are involved.
